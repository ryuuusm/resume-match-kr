# 이력서 구조와 표기 / Resume structure (KO & EN)

`match.py`는 Markdown 이력서를 읽는다. 아래 구조를 따르면 섹션·헤드라인·날짜를 정확히 인식한다.

## 공통 골격
```markdown
# 이름
헤드라인 (직무명 | 핵심 도메인 2~3개)
이메일 | 휴대폰

## 요약            (또는 Summary, 자기소개, 프로필)
## 경력            (또는 Experience, 경력사항, 경력기술서)
### 회사 · 직함 (2019.03 - 현재)
- 성과 문장
## 학력            (또는 Education)
## 기술            (또는 Skills, 보유 기술, 핵심역량, 자격)
- 분류: 항목, 항목, 항목
```
- 헤드라인 = `# 이름` 다음의 첫 줄(연락처 줄 제외).
- 인식하는 섹션 제목(부분 일치, 한·영): 요약·소개·프로필·summary·profile·about / 경력·근무·experience·employment / 학력·교육·education / 기술·스킬·역량·자격·보유·skills·technologies.
- 기술 섹션은 쉼표, `/`, `·`, `|`로 나눠 스킬 목록으로 읽는다. `언어: Python, SQL`처럼 앞의 분류명은 무시한다.

## 날짜 표기
| 스타일 | 예 | 메모 |
|-------|----|------|
| dot | 2019.03 | 국문 이력서에서 가장 흔함. 권장 |
| korean | 2019년 3월 | |
| iso | 2019-03 | |
| name_year | Mar 2019 | 영문 resume 권장 |
| year | 2019 | 연도만 |
한 문서 안에서 **한 가지 스타일**로 통일한다(날짜 일관성 점수). "현재", "재직중", "Present"는 세지 않는다.

## 국문 이력서 (국내 기업)
- 회사 지정 양식이 있으면 그 양식이 우선이다. 이 스킬은 내용(키워드·문장)을 맞추는 데 쓰고, 양식 칸에 옮겨 넣는다.
- 경력직은 이력서(요약표) + 경력기술서(프로젝트 단위 상세)를 따로 내는 경우가 많다. 두 문서를 각각 `match.py`로 확인한다.
- 블라인드 채용: 학교명, 사진, 생년월일, 가족관계, 출신지를 쓰지 않는다.

## 영문 resume (외국계)
- 1~2쪽. 사진·생년월일·성별·혼인 여부를 넣지 않는 것이 일반적이다.
- 경력 bullet은 동사로 시작(Led, Built, Reduced), 수치는 `40%`, `KRW 1.2B`처럼 통화 코드로.
- 직함은 사내 직급 대신 직무명. 한국 직급을 쓰려면 괄호로 병기: `IT Project Manager (Manager, 과장)`.
- 한국 회사·학교는 공식 영문명을 쓴다.

## PDF·DOCX 이력서
`match.py`는 텍스트만 읽는다. PDF/DOCX는 먼저 Markdown/텍스트로 옮긴다(에이전트가 파일을 읽어 변환하거나, 사용자가 붙여넣기). 2단 레이아웃·표·이미지 안의 글자는 ATS도 잘 못 읽으니, 변환 결과가 이상하면 그 자체가 개선 포인트다.
